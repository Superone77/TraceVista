# 第一批 · 2026-10-05

## 伸缩文字（ladder）断行
- 修正卡片文字以「: , .」开头的问题，例如「Python loop baseline」后一行以「, 3 to 17 ms」开头。
- 原因一：标点合并规则没有匹配带尾随空格的标点（", "），现在去掉空格再判断，标点跟在前一个词后面。
- 原因二：一串新出现的词被包成一个 inline-block，整块换行。现在只有保留下来的词是 inline-block（滑动动画需要），新出现的词按 inline 逐词换行。
- 涉及 `ZoomText.tsx`、`trajectory.css`。

## 侧栏：Details 与 Chat 不再遮挡地图
- Chat 从画布上的浮层改为和 Details 共用画布右侧的一栏（`side-dock`），地图不再被盖住。
- 两者都打开时，栏顶显示 Details / Chat 标签，一次显示一个，各自占满整栏高度。打开第二个面板不会让地图再变窄。
- 隐藏的 Chat 保持挂载，进行中的请求不会因为切到 Details 而中断。
- Chat 在前时点击地图卡片，只更新对话焦点，不跳到 Details；点击证据编号切到 Details。
- 工具栏按钮：面板未打开则打开；已打开但在后面则切到前面；已在前面则关闭。
- 窄于 1000px 的窗口里，这一栏浮在画布右侧（原有行为）。
- 涉及 `StateReader.tsx`、`interface.css`。

## 画布尺寸变化时的视野
- 侧栏开合导致画布变宽或变窄时，视野保持居中，并把选中的卡片挪回屏幕内。原来视野左对齐，选中的卡片可能被侧栏挤出屏幕。
- 画布窄于 1000px 时，Run overview 自动收起，侧栏关掉、画布变宽后自动恢复。
- 涉及 `StateReader.tsx`。

## 层级按钮的落点
- 工作阶段层：目标状态的标题和阶段行放在顶部，不再把状态中部放在屏幕中央。
- 动作层：目标所在列的工作阶段卡放在顶部，下面接这一列的动作。横向从这个状态的第一列开始尽量多显示几列，目标列始终在屏幕内。原来把第一张动作卡放在屏幕正中，阶段卡被切掉一半，左侧留白。
- 原始记录层：直接从目标卡片开始。
- 未选中卡片时，取离屏幕中心最近、且有工作阶段的状态。原来可能落在没有任何阶段的状态上，只看到一个空框。
- 涉及 `StateReader.tsx`。

## 没有工作阶段的状态
- 在工作阶段、动作、原始记录层只保留标题区高度（228），不再占一整层空白。
- 涉及 `semantic.ts`。

## 文档

# 第五批 · 2026-10-06

目标：除了 agent 的直接输入输出，所有再加工、生成的内容都能中英切换；删掉不承重的文字；缩小时节点更紧凑。

## 生成内容中英切换
- 规则：agent 自己说的和收到的（原始记录、从原始记录逐字摘出的引文）保持原文；其余所有分析者或模型写的内容都随界面语言切换，包括左栏故事线、状态/阶段/动作的标题与摘要、阅读层（主题、结论、理由）、全程概览、范围与备注、版本来源理由、测量说明、分类依据、状态转换说明、连线证据、观察摘要。
- 数据格式：轨迹文件可以带 `"i18n": {"zh": {"英文原句": "中文"}}`。查看器在界面语言与文件自身语言不同时逐条替换；替换后若主题不在结论里，取结论的第一个短语作主题，保证缩放文字仍能从主题长成结论。
- 新增 `localize.ts`；地图、故事线、详情读替换后的版本；导出仍写原文件（含翻译表），对话仍读原文。
- 五个内置示例都加了中文翻译表，覆盖全部 2,178 条分析者文字。翻译按示例分批完成，每批用脚本检查：键齐全、数字保留、主题在结论里、长度在阅读层预算内、不用破折号。InferenceBench 有 10 处提示是英文原文把小数点粘在前面（如「p50.4399」），译文写成「p50 0.4399」，属于修正，不是丢数字。Pi 示例两处同一主题的译法不一致（「19 项边界测试」「定稿」），已统一。
- 状态之间的连线标签（由这个版本派生、恢复这个版本、保留并收尾）改为随语言切换。

# 第六批 · 2026-10-06

目标：缩小后的状态卡仍然很空（截图：紧凑模式下一张高卡里只有一行结论）。

## 原因
- 第五批把紧凑模式的阈值从 30% 提到 36%；左右栏都打开时首屏缩放约 35%，于是一打开就是紧凑模式。
- 紧凑模式只放一行「编号 + 结论」，而卡片高度按完整内容估算。
- 卡片高度还按「结论 + 理由」那一档估算，这一档要缩放到 50% 才出现，此时已经进入工作阶段层，总览上从不显示，所以估高了。
- 普通模式在 33%–39% 之间，缩放文字可能退到只剩主题词，字大而短，底部的决策标签被挤出卡外。

## 修改
- 紧凑模式（缩放低于 36%）的卡片按当时的缩放填满：依次放编号、结论（加粗）、理由（灰）、测量，以及有空间时的编号决策标签；能放几行由卡片高度乘缩放算出，放不下的从后往前省略。行数只在增减一整行时重算，缩放时不会每一帧重绘全部卡片。
- 只有总览层的状态卡订阅缩放；其他卡片不受影响。
- 总览卡上的缩放文字最低停在「结论」这一档，不再退到只有主题词；更远的缩放交给紧凑模式。
- 卡片高度只按总览里实际显示的结论估算；有「恢复的版本」标记时测量行会换行，多预留一行。

## 讨论结论
- 原来六种线表达三种关系（版本、时间、原因），靠颜色和虚实区分；图按版本关系排布，读者却按时间读；最能体现流程的「转去做另一个阶段」画成半透明紫色弧线；时间和原因两种虚线相像；状态之间的箭头从框连到框，没有从做出改动的那一步连出去。

## 修改
- 总览层不变：版本树，深绿实线是继承，回退为紫色虚线并标「↶ 恢复这个版本」。
- 状态内以时间为轴：
  - 工作阶段按开始时间从左到右排列并编号（方框数字，与决策编号的圆形区分）；`phaseFlow` 按阶段内动作的最早时间排序，记录缺失时按文件顺序。
  - 先后相接的阶段之间画灰色实线箭头；开始时前一个阶段还没结束的，画灰色点线并标「同时进行」，不带箭头。
  - 工作阶段层新增从「做出改动的那个阶段」到它产生的下一个版本的绿色实线；动作层仍是从那个动作连出。时间因此从阶段接到下一个版本，不再从状态框连到状态框。
  - 数据里跨阶段的先后记录（原紫色弧线「接着做」）不再画，由上面的时间箭头代替。
  - 版本关系在状态内退为状态框之间的淡色宽带，不带箭头和文字，只有回退处标 ↶。
- 原因按需出现：蓝色虚线只在鼠标指向或选中的卡片上画出，标「因为」；平时卡片顶部有「因为 N」标记。
- 聚焦：工作阶段层及以下选中一张卡片，它连着的卡片（上一步、下一步、依据、产生的版本）和所在状态保持清楚，其余变淡；点空白处取消。
