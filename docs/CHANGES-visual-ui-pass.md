# 第一批 · 2026-10-05

## 伸缩文字（ladder）断行
- 修正卡片文字以「: , .」开头的问题，例如「Python loop baseline」后一行以「, 3 to 17 ms」开头。
- 原因一：标点合并规则没有匹配带尾随空格的标点（", "），现在去掉空格再判断，标点跟在前一个词后面。
- 原因二：一串新出现的词被包成一个 inline-block，整块换行。现在只有保留下来的词是 inline-block（滑动动画需要），新出现的词按 inline 逐词换行。
- 涉及 `ZoomText.tsx`、`trajectory.css`。

## 侧栏：Details 与 Chat 不再遮挡地图
- Chat 从画布上的浮层改为和 Details 共用画布右侧的一栏（`side-dock`），地图不再被盖住。
- 两者都打开时，栏顶显示 Details / Chat 标签，一次显示一个，各自占满整栏高度。打开第二个面板不会让地图再变窄。
- 隐藏的 Chat 保持挂载，进行中的请求不会因为切到 Details 而中断。
- Chat 在前时点击地图卡片，只更新对话焦点，不跳到 Details；点击证据编号切到 Details。
- 工具栏按钮：面板未打开则打开；已打开但在后面则切到前面；已在前面则关闭。
- 窄于 1000px 的窗口里，这一栏浮在画布右侧（原有行为）。
- 涉及 `StateReader.tsx`、`interface.css`。

## 画布尺寸变化时的视野
- 侧栏开合导致画布变宽或变窄时，视野保持居中，并把选中的卡片挪回屏幕内。原来视野左对齐，选中的卡片可能被侧栏挤出屏幕。
- 画布窄于 1000px 时，Run overview 自动收起，侧栏关掉、画布变宽后自动恢复。
- 涉及 `StateReader.tsx`。

## 层级按钮的落点
- 工作阶段层：目标状态的标题和阶段行放在顶部，不再把状态中部放在屏幕中央。
- 动作层：目标所在列的工作阶段卡放在顶部，下面接这一列的动作。横向从这个状态的第一列开始尽量多显示几列，目标列始终在屏幕内。原来把第一张动作卡放在屏幕正中，阶段卡被切掉一半，左侧留白。
- 原始记录层：直接从目标卡片开始。
- 未选中卡片时，取离屏幕中心最近、且有工作阶段的状态。原来可能落在没有任何阶段的状态上，只看到一个空框。
- 涉及 `StateReader.tsx`。

## 没有工作阶段的状态
- 在工作阶段、动作、原始记录层只保留标题区高度（228），不再占一整层空白。
- 涉及 `semantic.ts`。

## 文档
- `docs/VIEWER.md`：更新层级落点、侧栏和视野的说明。

## 验证
- `pnpm test` 全部通过，`pnpm build` 通过。
- 浏览器实测（1500×920，Chrome）：Pi Agent 四个层级、Details 与 Chat 的各种开合组合、对话中点卡片；LiteResearcher 的工作阶段层。无页面报错。
- 未测：真实模型对话（没有配置 key）、触控板手势、窄屏与手机布局。

## 本批未处理

- 固定高度卡片的空白、卡片底部约 7px 的动作计数小字。
- 底部图例在动作层会压住卡片。

# 第二批 · 2026-10-06

目标：视觉上有重点；简化；展开用伸缩文字式的过渡，不让信息一次压过来；帮读者找到关键决策点、看懂每一步主要做了什么。所有规则只依据图本身的结构，不针对任何 agent 或任务。

## 交付主线（地图）
- 时间顺序的终点（没有后续转换的状态）记为交付状态，状态卡标「Delivered」并加紫色外圈。
- 从交付状态沿当前状态关系往上追，得到交付主线。主线连线加粗；主线外的状态和它内部的阶段、动作卡变淡，标「Side branch」，鼠标指向或选中时恢复。
- 线性运行（所有状态都在主线上）不画支线，不做淡化。
- 首屏按主线的横向跨度取景，缩放不低于 26%。PostTrainBench 现在一打开就能看到 S0、S4、S5 到交付的 S10。
- 涉及 `story.ts`（新）、`StateReader.tsx`、`MapCard.tsx`、`story.css`（新）。

## 关键决策统一编号
- 每个状态取工作阶段层的排除、决定、转向、未决；不足两个时补动作层的，最多四个；按运行先后编号。
- 同一编号出现在左栏、状态卡上的决策标签、阶段卡和动作卡的标记、详情面板里。
- 状态编号 S0、S1… 改为按状态出现的先后，不再随版本树排布变化（原来 PostTrainBench 的 s10 显示为 S8）。

## 左栏 Run overview（替换浮在地图上的概览面板）
- 固定在地图左侧，各层都在，不再遮挡卡片。
- 历程段落只显示前两句，「More」在原处展开其余部分和它引用的节点。
- 交付状态一张卡片，点击定位。
- 「Steps and key decisions」：每个状态一行，写它得出了什么、做了多少动作、主要是哪两类行为（如「38 actions · mostly Edit & Verify」），下面是编号的关键决策，每条一行。
- 点击决策：理由和原文摘句在这一行下面展开，地图跳到它所在的阶段层或动作层，单个动作居中显示。在地图上选中决策时，左栏同步展开并滚到那一行。
- 「Hide」收起，画布左上角「Overview」重新打开；画布窄于 600px 时自动收起（例如 1280 宽的窗口打开详情时），变宽后恢复。
- 涉及 `StoryRail.tsx`（新）、`Stretch.tsx`（新）、`StateReader.tsx`、`story.css`。

## 卡片简化
- 状态卡右上角的「N stages · M actions」改为「M actions · mostly A & B」，说明这一步主要在做什么。
- 没有测量的状态不再显示「No comparable measurement」。
- 工作阶段卡底部的动作计数从约 6px 放大到约 9px（屏幕尺寸）。
- 动作数为 1 时写「1 action」。
- 涉及 `MapCard.tsx`、`story.css`。

## 详情面板分层
- 先给核心：这一步新增了什么、测量结果或行为类别、这一步里的关键决策（带编号）、支撑它的观察与它影响的决定。
- 其余内容各自折叠，点击在原处展开（高度与透明度一起过渡）：What happened、Quoted evidence、Results and comparison、Version origin、Phases and actions、Classification basis、Tracked state、Execution order、Related actions、Structure and evidence、Source records、What this graph tracks。
- 从证据编号打开的原文显示在核心内容下方，不用滚到底。
- 未选中卡片时的总览页（Structure & evidence）保持原有内容。
- 涉及 `Inspector.tsx`、`story.css`。

## 对话框简化
- 未连接模型时，不再一打开就铺满 API 设置表单，只显示一张「Connect a model」卡片。
- 标题栏只留：模型按钮（连接后显示模型名，点击展开设置）、「⋯」菜单（导出、清空）、关闭。
- 上下文范围、额度两行和请求预览折叠成一行「Context · Smart context · ~N tokens」，点击展开。
- 对话逻辑、上下文选择、额度检查都没有改。
- 涉及 `ChatDialog.tsx`、`story.css`。

## 过渡与图例
- 切换层级时，新出现的卡片在落点淡入，地图像是在原处展开而不是突然切换。
- 左栏的「More」、决策展开、详情的折叠区块都用同一种高度与透明度的过渡。
- 系统设置「减少动态效果」时不做动画。
- 图例默认收成左下角的「Legend」按钮，不再压住卡片；状态层图例加「Delivered line」。
- 涉及 `StateReader.tsx`、`story.css`。

## 文档
- `docs/VIEWER.md`：更新交付主线、状态卡、详情、关键决策编号、左栏、过渡、图例和对话框的说明。

## 验证
- `pnpm test` 全部通过，`pnpm build` 通过。
- 浏览器实测（Chrome）：1500×920 下 Pi Agent、PostTrainBench、InferenceBench 的总览，Pi 的左栏决策点击（阶段层和动作层各一个）、详情、对话；1280×800 下左栏随详情自动收起和恢复。无页面报错。
- 未测：真实模型对话（没有 key）、触控板手势、手机布局。

## 本批未处理
- 卡片固定高度造成的空白（工作阶段卡）。
- 原来的浮动概览面板（`.journey`）样式还留在 `trajectory.css` 里，已不再使用。
- 与 PR #10 的冲突仍需按先合入的一方调整。

## 左栏 Story（故事线）
- 左栏原来的「Run overview」（步骤列表加编号决策）换成故事线，组件仍是 `StoryRail.tsx`，内容和排版沿用草图：
  - 暖白纸色底、衬线正文（系统自带字体，不新增外部请求）、小号无衬线界面标签。
  - 顺序：项目名；「How the agent got there」；交付了什么；两句概况，「More」在原处展开其余部分和引用的节点；每个状态一句（得出了什么、为什么）。
  - 页边一条细线串起各步：实心点是主线，空心点是被放下的尝试（写「A side attempt」），紫点是交付。
- 点一句话，下一层在这句话后面长出来，后面的文字往下让：状态展开成工作阶段，阶段展开成动作，动作展开成 agent 写下的话或工具返回的原文（等宽框，标明「The agent wrote」或「The tool returned」，编号可在 Details 打开完整记录）。
- 决策写成动词：Changed course、Ruled out、Decided、Left open、Found，前面带全局编号（与地图卡片上的编号一致）；动作写成 Looked into、Planned、Changed、Ran、Checked、Diagnosed；没有阅读层标注的常规动作折成一句「…and N routine steps」。

- `Stretch.tsx`：内容第一次挂载时也从收起状态长出来。

## 飞行定位
- 展开一句时地图镜头飞到同一处，深度与文字一致：交付句到总览层的终点状态；状态到工作阶段层；阶段到动作层的那一列；动作到原始记录层的那张卡（并选中）。
- 同一层内平滑平移缩放（约 0.5 秒）。跨层时先在屏幕中心处换上目标层的布局，再飞到目标；飞行途中不按缩放自动切换层级，读者自己拖动或缩放即刻接管。系统设置「减少动态效果」时直接跳到目标。
- 工具栏层级按钮（含回到总览）、对话引用、详情里的跳转都改用同一种飞行。
- 工作阶段层一行比屏幕宽、又没有指定具体阶段时，从这一行的左边开始显示。
- 反过来：在地图上点卡片，故事线展开到这张卡所在的那一句并滚过去；右侧 Details 照常打开。
- 涉及 `StateReader.tsx`。
