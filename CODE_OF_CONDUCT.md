# Code of Conduct

TraceVista welcomes people with different backgrounds, experience levels, and perspectives. This code applies to project issues, pull requests, discussions, and other spaces maintained for the project. It also applies when someone represents TraceVista publicly.

## Working together

- Treat people with respect. Critique ideas and code with specific, useful feedback.
- Be patient with questions and mistakes. Explain assumptions and make room for different experiences.
- Respect privacy. Do not share private conversations, credentials, or personal information without permission.
- Do not harass, threaten, discriminate against, or sexually target others. Personal attacks, repeated unwanted contact, and retaliation against someone who raises a concern are unacceptable.

## Reporting and response

Report concerns privately to maintainer Wanqi Yang at [yangwq177@gmail.com](mailto:yangwq177@gmail.com), the contact listed on his [public profile](https://superone77.github.io/). Include relevant links and enough context to understand what happened. Do not publish sensitive details in an issue to make a report.

For abusive behavior on GitHub, you can also use the affected content's **Report content** menu or [report it to GitHub Support](https://support.github.com/contact/report-abuse), including when a complaint concerns a maintainer. [GitHub's reporting guide](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam) explains the available options. This route is handled by GitHub.

Project maintainers are responsible for moderating project spaces. They may edit or remove content, ask someone to change their behavior, restrict participation, or block an account, according to the severity and repetition of the behavior. Reports involving a maintainer should be handled by an uninvolved maintainer where one is available; GitHub Support remains available for GitHub policy violations. Reports should be reviewed fairly, and personal details shared only as needed to address the concern.

Technical vulnerabilities have a separate reporting process in [SECURITY.md](SECURITY.md).
